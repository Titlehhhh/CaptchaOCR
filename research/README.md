# research/ — рабочие материалы, а не часть проекта

Здесь лежит всё, что нужно было, чтобы **написать** генераторы, но что не нужно, чтобы их
**использовать**: реверс-инжиниринг чужих плагинов, эталонные прогоны и черновые скрипты
веб-поиска. Ни один файл из этой папки не участвует в сборке датасета и не входит в публикуемый
датасет.

| путь | что это | в git |
|---|---|---|
| `jars/`, `decompiled/`, `cvz*/`, `cfr.jar` | апстрим-джары и их декомпиляция (CFR) | **нет** (`.gitignore`) |
| `limbofilter/` | декомпиляция **Elytrium/LimboFilter** (AGPL-3.0) | **нет** (`.gitignore`) |
| `refout/` | 5 эталонных рендеров CaptchaVerifyZ — эталон для проверки пикселей | да |
| `myout/` | вывод `DiffCaptchaVerifyZ.java` — байт-в-байт то же, что `refout/` | **нет** (`.gitignore`) |
| `tools/` | черновые скрипты веб-поиска (парсеры страниц spigotmc.ru, движков) | да |
| `*.java`, `*.md` | `DiffCaptchaVerifyZ.java` (проверка пикселей), `RefRender.java`, `FontInfo.java`, заметки | да |

## Почему `limbofilter/` убран из публичного дерева

Шесть файлов в `limbofilter/` — это декомпиляция **Elytrium/LimboFilter**
(<https://github.com/Elytrium/LimboFilter>), лицензия **AGPL-3.0**, и авторские заголовки в них
сохранены нетронутыми. Публиковать чужую декомпиляцию в открытом репозитории — правовой риск:
распространение AGPL-кода тянет за собой требование предоставить исходники под той же лицензией.

Файл `dataset/generator_ru/dev/captcha/gens/LimboFilter.java` — **наша** переработка того же
алгоритма, написанная с нуля по поведению (clean-room), и в ней нет чужих идентификаторов.
Поэтому в репозитории остаётся генератор и ссылка на апстрим, а не декомпиляция.

Каталог `limbofilter/` остаётся на диске локально (он в `.gitignore`), чтобы его можно было
перечитать при необходимости. Если он нужен для проверки — читайте его локально, в публикуемое
дерево он не попадает.

## `myout/` против `refout/`

`research/DiffCaptchaVerifyZ.java` рендерит пять кодов нашим генератором и складывает результат в
`research/myout/`. Эти пять PNG **байт-в-байт совпадают** с `research/refout/` (одинаковый MD5) —
это и есть измеренный факт проекта: наш рендер `CaptchaVerifyZ` даёт 0 отличающихся пикселей из
16 384 и равный MD5. Держать обе копии в git незачем, поэтому в репозитории остаётся `refout/`
(его использует `tools/restore_real_shots.py`), а `myout/` перегенерируется пробой и в git не входит.
