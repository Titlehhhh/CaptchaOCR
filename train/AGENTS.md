# AGENTS.md — обучение и оценка (`train/`, `bench/`)

**Этот файл — вложенное правило. Он выигрывает у корневого `AGENTS.md` для файлов в `train/`
и `bench/`.** Корневые правила (главный агент — оркестратор, один файл — один агент, не выдумывать
источники, не редактировать измеренные результаты) действуют и здесь.

---

## 1. Чем запускать

```powershell
.venv-gpu\Scripts\python.exe train\train.py --charset latin --trees both --epochs 80 --workers 6
```

- **`.venv-gpu\Scripts\python.exe` — единственный правильный интерпретатор для обучения**
  (torch 2.14.1+cu126, CUDA, sm_61 для GTX 1080 Ti 11.8 ГБ). **Системный python — CPU-only**:
  на нём обучение идёт в ~9 раз медленнее, и это ловушка.
- `ddgs`/кириллица: `$env:PYTHONIOENCODING="utf-8"`.
- `build.ps1` не выполняется (`.ps1` заблокирован) — логику вставляй inline.

## 2. Флаги (реальный список из `train/train.py`)

| флаг | смысл |
|---|---|
| `--charset latin|cyrillic` | набор классов; по умолчанию `latin` (63 класса) |
| `--types` / `--val-types` | подстроки-фильтры по id типа (обучающие / удержанные) |
| `--exclude-types` | дополнительно исключить типы |
| `--trees out|out_ru|both` | какое дерево датасета брать |
| `--allow-no-roi` | **разрешить** типы без полосы; по умолчанию они **исключаются** |
| `--epochs`, `--batch-size`, `--lr`, `--head-lr` | базовая настройка; по умолчанию lr 3e-3, head lr = lr/10 |
| `--glyph-height` | высота глифа в пикселях после масштабирования (по умолчанию 32) |
| `--workers` | воркеры даталоадера; на GPU декодирование картинок — узкое место, ставь 4-6 |
| `--augment-affine` | включить поворот/сдвиг/масштаб (в коде есть, прогон с ним не измерен) |
| `--no-augment` | выключить всю аугментацию |
| `--out`, `--save-every`, `--resume` | куда писать чекпоинты, как часто, продолжить с последнего |
| `--device auto|cuda|cpu`, `--amp/--no-amp` | железо и смешанная точность |
| `--seed`, `--limit-per-type`, `--log-every`, `--threads` | воспроизводимость и отладка |

**Флага `--require-roi` не существует.** Типы без полосы исключаются **по умолчанию**; флаг
`--allow-no-roi` их, наоборот, **разрешает** (это некорректно поставленная задача «найди строку
в этой картинке» — на ней модель учится читать не ту строку).

## 3. Три правила, которые экономят часы

**1. Плато all-blank — это не баг.** CTC сначала выучивается выдавать один только blank: лосс висит
на **ln(63) = 4.14** и ползёт вниз **тысячи шагов**. Наш прогон: плато пройден к ~1000 шагу, к
5700 шагов лосс 0.005. **Плоский лосс на первых тысячах шагов — не повод «чинить» модель.**

**2. Полоса важнее модели.** Модель получает **кроп по `roi`**, а не весь кадр. На кадрах точность
падает в 16–67 раз (измерено на 9 моделях, `reports/bench_models/`). **Неверная полоса хуже, чем её
отсутствие**: метку невозможно подогнать, лосс не идёт вниз, и валидатор это не ловит. Проверяй
полосу глазами (`tools/check_band_vs_answer.py`, контактные листы в `reports/`).

**3. Разбиение — только по типам.** Никогда random split: при нём **34.3 %** тестовых сэмплов имеют
свой точный золотой ответ в обучающей половине, а 9 типов протекают на 100 %. Единица обобщения —
**плагин**, а не картинка. Метрики: **exact match и CER, пер-тип + медиана по типам** (медиана, а не
среднее: один тип двигает среднее сильнее всех остальных вместе).

## 4. Куда писать результаты

| что | куда |
|---|---|
| JSON результатов замера | `reports/bench_models/<что>.json` |
| измерения чужих моделей по единому протоколу | `bench/bench_models.py` (харнесс), результат — в `reports/bench_models/` |
| текстовый отчёт об эксперименте | `reports/TRAINING_MINIMAL_LATIN.md` (существующий) или новый отчёт в `reports/` |
| чекпоинты и логи | `train/run/**` — **в gitignore**, на диске |

**Существующие измеренные результаты не правятся руками** (`reports/bench_results*.json`,
`reports/bench_models/*.json`): перезамеряем и пишем новое.

**Датасет — выборка, а не воспроизводимая сборка:** генераторы **не засеяны**, поэтому пересборка
даёт другой набор случайных сэмплов (шрифты AWT те же, но текст, шум и композиция — новые).
Мы учимся с той же папки, что и сгенерировали; продолжение прогона (`--resume`) имеет смысл
только на ней же. Измерение всегда ведётся на конкретной папке — «пересоберём и получим то же
самое» здесь неверно.

## 5. Известные открытые проблемы (не «чинить» молча)

- **Model B (кириллица) собирает 34 класса, а план требует 44** (`captcha_crnn.py`: `CYRILLIC` = 33
  буквы). Цифры в метках `LimboFilter/symbols` и `GalleryCaptcha/ru-symbols` **молча выпадают** (35–43 строки
  из 100). Расширение charset требует проверки прогоном на кириллице.
- **Два бага в датасете починены 2026-10-22, датасет пересобран** (правки в генераторах, не здесь):
  полоса `Archy-X/Krypton/map` была на 4 px ýже текста — теперь `band()` прибавляет
  `code.length()-1`; в `text` типа `LagBug/XProtect/reverse` лежала перевёрнутая строка — теперь
  `text()` возвращает нарисованный код. Оба — в `docs/adr/0001-dataset-is-kept-in-git.md` и
  `reports/TRAINING_MINIMAL_LATIN.md` §7.
- **Готовые движки лучше нашей модели на невиданных типах** (PP-OCRv6: 0.40 против наших 0.000) —
  см. `reports/CAPTCHA_SYSTEM_OVERVIEW.md`. Это не повод выбрасывать свою модель, а повод взять
  чужую за базу.
