# GLOSSARY — словарь проекта CaptchaOCR

**Дата:** 2026-10-22. Термины — из `HANDOVER.md` и `agents/INDEX.md`, примеры — из наших же данных
(`dataset/out/**/labels.jsonl`, `reports/bench_models/*.json`).

---

## Данные

**Тип (captcha type)** — одно семейство капч от одного плагина. У нас их **46**: 34 в `dataset/out/`
(18 плагинов верхнего уровня `owner/repo`) и 12 в `dataset/out_ru/` (плоские имена плагинов).
Примеры: `CaptchaVerifyZ/map`, `GalleryCaptcha/ru-web`, `LagBug/XProtect/code`.

**`out` vs `out_ru`** — два дерева датасета. `dataset/out/` — переписанные по апстриму плагины
(18 штук, два уровня вложенности: `owner/repo/type`). `dataset/out_ru/` — семейства каталога
`GalleryCaptcha` и найденные при разборе источники (5 штук, один уровень: `Plugin/type`).

**Группа A / B / C** — какого рода задача тип:
- **A — чистый OCR** (20 типов, 2000 картинок): ответ буквально нарисован;
- **B — OCR + шаг solver'а** (11 типов, 1100): картинку прочитать можно, но игрок вводит другое
  (развернуть строку, посчитать выражение, слова-числа → цифры);
- **C — не OCR** (15 типов, 1500): ответа в картинке нет вовсе или он не текст (цвет, номер слота,
  константа). Проверено по `labels.jsonl` 2026-10-21, см. `agents/INDEX.md` §4.

**`text`** — строка, **которая нарисована** на картинке. Это то, что учит распознаватель.
Пример: `LimboFilter/map` — на картинке «шестьсот девяносто», в `text` лежит `шестьсот девяносто`.

**`answer`** — строка, **которую вводит игрок**. В 37 типах из 46 `text == answer`; расходятся они
в 8 типах: три арифметических (`LagBug/XProtect/equation` — на картинке `19 - 11`, ответ `8`),
три с русскими словами-числами (`GalleryCaptcha/ru-numberword`, `ru-numberword-caption`, `LimboFilter/map`)
и два с теми же словами в повёрнутых рамках (`LimboFilter/framed2x2`, `framed3x3`).

**`roi` (полоса)** — прямоугольник `[x, y, w, h]` в пикселях холста, **в котором нарисован ответ**.
Пример: `CaptchaVerifyZ/map` — холст 128×128, `roi = [26, 48, 75, 28]`.
Правило, из которого выросли все полосы: **полоса, которая не помещается в кадр, — это не полоса**;
`roi()` возвращает `null`, а не прямоугольник, в который попал только кусок ответа.
29 типов из 46 несут полосу, 17 — нет (у них `roi = null`).

**`real_shots/`** — настоящие скриншоты, а **не** обучающие данные: 1240 картинок реального вывода
источников (группа GalleryCaptcha 674, BotFilter 510, LimboFilter 49, CaptchaVerifyZ 5, WeatherActionCaptcha 2).
Это материал для сверки, и удалять их нельзя.

**`site/captchas/`** — 525 референсов группы типов GalleryCaptcha (11 секций по версиям API). Тоже **не**
обучающие данные: истинного ответа по ним нет, поэтому любая «точность» на них не проверяема.

**faithful / clean-room / reconstructed** — режим, в котором сделан генератор:
- **faithful** — построчная перереализация из апстрима (лицензия это позволяет);
- **clean-room** — алгоритм прочитан и написан заново, без кода и идентификаторов апстрима;
- **reconstructed** — апстрим не найден, тип восстановлен по эталонным скриншотам.
Режим виден в `labels.jsonl` в поле `source` (`класс#метод` апстрима, для clean-room — описание).

## Распознавание

**кадр** — вся картинка целиком. **полоса** — вырезанный прямоугольник с ответом.
Модель получает **полосу**, а не кадр: измерено, что на кадрах точность падает в 16–67 раз
(см. `reports/bench_models/`), и на живом коммерческом API — с 75 % до 0 %.

**глиф** — нарисованный символ. «Высота глифа» (x-height/капитал) — величина, по которой
масштабируют: **до 32 px глиф, а не кадр**. Отсюда правило: кадр 250×150 и кадр 128×128
дают в сеть разное.

**временные шаги (T)** — сколько позиций по времени выдаёт сеть. У нас три пулинга
`(2,2), (2,2), (2,1)` → T = W/4. Ограничение CTC: **T ≥ 2L + 1**, где L — длина ответа
(значит, ширина входа W ≥ 4(2L+1)).

**CTC** — лосс, где модель выдаёт распределение по позициям, а ответ собирается collapse'ом
повторов и удалением blank. Не требует выравнивания метки по картинке, поэтому быстрый.
**attention-декодер** — альтернатива, точнее на длинных текстах, но медленнее; **GTC** — гибрид,
где attention направляет CTC-обучение (есть в PP-OCRv5).

**all-blank плато** — состояние, из-за которого новички считают модель сломанной: CTC сначала
выучится выдавать один только blank, лосс висит на **ln(63) = 4.14** и ползёт вниз **тысячи шагов**.
Плоский лосс на первых тысячах шагов — **не баг**. Наш прогон: плато пройден к ~1000 шагу,
к 5700 шагов лосс 0.005.

**per-character posterior** — уверенность модели в каждом символе отдельно. Из неё строится
и human-in-the-loop («звенит — спроси человека»), и калибровка. В наших неверных ответах

**int8 / динамическая квантизация** — сжатие весов в 8 бит. Наш замер: fp32 18.5 МБ → int8 dynamic
**4.7 МБ без потери точности**; статическая int8 — хуже (0.5746 против 0.6006). На CPU без VNNI
int8 даже **медленнее** fp32, то есть это про размер, а не про скорость.

**CER (Character Error Rate)** — доля неверных символов: (замены + вставки + удаления) / длина эталона.
**exact match** — точность полного совпадения строки. Для капч важнее exact match: «почти правильно»
игроку не годится.

## Оценка

**type-held-out** — разбиение **по типам**, а не по картинкам: целый тип капч уходит в валидацию.
Причину измеряли: при random split **34.3 %** тестовых сэмплов имеют свой точный золотой ответ
в обучающей половине, а 9 типов протекают на 100 %.

**пер-типовые метрики + медиана** — метрика считается по каждому типу отдельно, а сводной числом
берётся **медиана по типам**, а не среднее: один тип двигает среднее сильнее, чем все остальные
вместе.

## Конвейер

**кроппер** — код, который знает, **где** в картинке ответ (фиксированный прямоугольник, поиск
по шаблону «строка после `Tries Left:`» или детектор текста). Это **не модель**.

**распознаватель** — общая модель, читающая полосу в строку. Дополняется бесплатными подсказками
плагина: маска по алфавиту (`BotFilter` → только цифры), точная длина (`CaptchaVerifyZ` → ровно 5),
список кандидатов полосы.

**solver** — детерминированные правила после распознавания: развернуть строку, посчитать выражение,
перевести русские слова в цифры. Сейчас **не написан**.

**human-in-the-loop** — схема «модель не уверена → спросить человека». Требует, чтобы модель
отдавала уверенность, а не только строку.
