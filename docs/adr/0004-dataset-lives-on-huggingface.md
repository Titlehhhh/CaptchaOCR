# ADR 0004 — Датасет живёт на Hugging Face, а не в git

**Дата:** 2026-10-22 · **Статус:** принято · **Решение автора проекта:** владелец
**Заменяет:** ADR 0001 («Датасет остаётся в git»)

## Контекст

Репозиторий готовится к публикации как **CaptchaOCR** — лабораторный проект по машинному зрению.

Сгенерированный датасет — это **4600 размеченных PNG** (46 типов по 100) плюс `labels.jsonl` на
каждый тип. Измерено на этой машине:

| что | сколько |
|---|---|
| 4600 размеченных PNG (полезная нагрузка) | **43.6 МБ** |
| 517 эталонных скриншотов `real_shots/` | 3.3 МБ |
| полный git-репозиторий с историей (`git count-objects -vH`) | **141.6 МиБ** (`size-pack`) |

Проблема не в размере файлов, а в том, как работает git: **каждая ревизия остаётся в `.git`
навсегда**. Удаление картинок из рабочей копии не уменьшает репозиторий — история остаётся, и
клонирование тянет за собой все прошлые версии. Для набора, который пересобирается и меняется
целиком, это ровно тот случай, где полезная нагрузка должна жить не в истории исходников.

Дополнительно: датасет — **артефакт, а не функция** (системные шрифты AWT зависят от машины, см.
`HANDOVER.md` §4), поэтому публикуется именно **готовая отрисованная картинка**, а не только
код генератора. И ещё: у апстримов **разные лицензии** (GPL-3.0, AGPL-3.0, MIT, CC0 и «лицензии
нет»), поэтому один монолитный датасет на всех нельзя публиковать как «один домен» — его надо
делить по семействам лицензий.

## Решение

**Полный датасет публикуется в отдельном датасет-репозитории на Hugging Face.**
В git-репозитории остаются:

* генераторы на Java 21 (`dataset/generator/`, `dataset/generator_ru/`) — источник истины;
* разметка `labels.jsonl` на каждый тип;
* по 3–5 картинок на тип — чтобы посмотреть глазами, не скачивая весь набор;
* весь код обучения, бенчмарков и проверок.

Скачивание — одной командой:

```powershell
python tools\fetch_dataset.py
```

(скрипт `tools/fetch_dataset.py`; флаги `--dry-run`, `--types`, `--dest`, `--repo-id`,
`--cache-dir`. Без него — `python -c "from huggingface_hub import snapshot_download;
snapshot_download(repo_id='Titlehhhh/captchaocr-dataset', repo_type='dataset',
local_dir='dataset/full')"`.)

Публикация разбита **по семействам лицензий**: в каждой записи указан режим
(faithful / clean-room / reconstructed) и лицензия апстрима.

## Раскладка — что где лежит

### В git-репозитории `Titlehhhh/CaptchaOCR`

| Путь | Что это | Объём |
|---|---|---|
| `dataset/generator/`, `dataset/generator_ru/` | генераторы на Java 21 — источник истины | — |
| `dataset/out/<owner>/<repo>/<type>/labels.jsonl` | разметка 34 типов | 34 файла |
| `dataset/out_ru/<Plugin>/<type>/labels.jsonl` | разметка 12 типов | 12 файла |
| `dataset/out/index.html`, `dataset/out_ru/index.html` | контактные листы деревьев | 2 файла |
| `dataset/samples/<plugin>/<type>/001.png … 005.png` | **по 5 картинок на тип** — витрина | 230 PNG, 2.2 МБ |
| `dataset/samples/README.md`, `dataset/samples/index.html` | список типов и витрина с ответами | 2 файла |
| `tools/fetch_dataset.py` | скачивание полного датасета с Hugging Face | 1 файл |

Правила `.gitignore`, которые это обеспечивают:

```
dataset/out/**/*.png
dataset/out_ru/**/*.png
dataset/full/
```

`labels.jsonl` и `index.html` под правила не попадают — они остаются отслеживаемыми.
Правило `dataset/out_ru/**/*.png` заодно убирает из индекса эталонные скриншоты
`real_shots/` (517 файлов) — чужие скриншоты в публику не идут.

**Картинки датасета в git не лежат вообще.** После исключения PNG индекс репозитория
содержит **518 файлов, 23.5 МБ** (из них 15.2 МБ — измеренные результаты в `reports/`,
2.25 МБ — новые образцы, 1.4 МБ — разметка и генераторы); сами 4600 PNG дают 0 байт.

### На Hugging Face — `Titlehhhh/captchaocr-dataset`

| Путь | Что это | Объём |
|---|---|---|
| `out/<owner>/<repo>/<type>/001.png … 100.png` | 34 типа × 100 PNG | 3400 PNG |
| `out/<owner>/<repo>/<type>/labels.jsonl` | разметка тех же 34 типов | 34 файла |
| `out_ru/<Plugin>/<type>/001.png … 100.png` | 12 типов × 100 PNG | 1200 PNG |
| `out_ru/<Plugin>/<type>/labels.jsonl` | разметка тех же 12 типов | 12 файла |
| `index.html`, `README.md`, карточка датасета | описание и контактные листы | — |

Итого на Hugging Face: **4600 PNG, 43.6 МБ**, 46 `labels.jsonl`.
Эталонные скриншоты `real_shots/` на Hugging Face **не выкладываются**.

### Сколько весит датасет (измерено на этой машине)

| что | сколько |
|---|---|
| 4600 размеченных PNG (полезная нагрузка) | **43.57 МБ** |
| 517 эталонных скриншотов `real_shots/` | 3.30 МБ |
| 230 образцов в `dataset/samples/` | 2.21 МБ |
| полный git-репозиторий с историей (`git count-objects -vH`) | **141.64 МиБ** (`size-pack`) |
| индекс git после исключения картинок датасета | **23.50 МБ** в 518 файлах |

## Последствия

* **Плюс.** Клонирование репозитория становится лёгким; датасет версионируется отдельно и
  обновляется по кускам; лицензионные обязательства видны явно.
* **Плюс.** Появляется место для выкладки самой модели на Hugging Face — тот же маршрут, что и для
  датасета.
* **Минус.** Обучение требует скачать датасет отдельно; «склонировал и сразу обучил» больше не
  работает. Это осознанный размен.
* **Минус.** Нужен явный процесс публикации: пересобрали генераторы — перезалили датасет на HF.
* **Следствие для правил репозитория.** Эталонные скриншоты `real_shots/` — это чужие
  скриншоты; в публику они не идут. Материалы сторонних коммерческих сервисов не используются и
  не публикуются ни в датасете, ни в репозитории.
* **Следствие для ADR 0001.** Решение «датасет остаётся в git» больше не действует: сам датасет
  уезжает на Hugging Face, а в git остаются только генераторы и разметка. Открытые замечания
  ревью генераторов из ADR 0001 при этом остаются в силе — они касаются кода, а не места
  хранения датасета.
