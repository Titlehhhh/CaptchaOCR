# DATASET_FORMAT — контракт данных

Датасет — это PNG-файлы плюс разметка. Разметка лежит **рядом с картинками**: на каждый тип
капчи — один файл `labels.jsonl`, в котором **одна строка JSON на каждый сэмпл**, в том же
порядке, что и `001.png`, `002.png`, …

## Пути

```
dataset/out/<owner>/<repo>/<тип>/NNN.png  + labels.jsonl    # 34 типа: owner/repo из апстрима
dataset/out_ru/<Плагин>/<тип>/NNN.png     + labels.jsonl    # 12 типов: плоское имя плагина
```

## Поля `labels.jsonl`

Ровно десять ключей в каждой строке:

| Поле | Что это |
|---|---|
| `file` | имя PNG внутри каталога типа, например `001.png` |
| `plugin` | плагин-источник (совпадает с каталогом уровнем выше) |
| `captcha` | тип капчи (совпадает с именем каталога) |
| `answer` | что игрок должен ввести. Регистр и формат значимы |
| `text` | что **нарисовано** на картинке |
| `prompt` | текст задания, который видит игрок |
| `roi` | прямоугольник полосы с ответом `[x, y, w, h]` или `null`, если полосы нет |
| `width`, `height` | размер картинки в пикселях |
| `source` | класс и метод апстрима, откуда взят алгоритм (аудит-тропа) |

## `text` vs `answer`

Это **не одно и то же**, и в 9 типах из 46 они различаются:

* `text` — то, что физически нарисовано на картинке;
* `answer` — то, что игрок должен ввести в поле ответа.

Расхождения бывают трёх видов:

| Тип | Что нарисовано (`text`) | Что вводится (`answer`) |
|---|---|---|
| `LagBug/XProtect/equation`, `FeelingAlive0/AdvancedCaptcha/math`, `Mrbysco/Captcha/math` | арифметический пример | результат примера |
| `GalleryCaptcha/ru-numberword`, `GalleryCaptcha/ru-numberword-caption`, `LimboFilter/map` | число словами по-русски | само число цифрами |
| `LagBug/XProtect/reverse` | строка | та же строка, но **перевёрнутая** |

**Практическое правило для обучения и оценки:** распознавать надо `text`, а «полное решение
капчи» — это `answer`. Считать accuracy модели по `answer`, не развернув строку и не посчитав
пример, — ошибка протокола.

Полный список типов с несовпадением — `agents/INDEX.md` §4.1 (пересчитывается по `labels.jsonl`).

## Правило полосы

> **Полоса, которая не помещается в кадр, — это не полоса.**

Если в прямоугольник попало только часть ответа, `roi` возвращается как `null`, а не как
обрезанный прямоугольник.

* Полосу несут **29 типов из 46** (28 — на всех 100 сэмплах, `haq/mapcha/map` — на 99).
* Строк с `roi = null` — **1701** (= 17 типов × 100 + 1). У остальных типов ответ либо
  занимает весь кадр, либо его в кадре нет вообще.

Полоса — не украшение: главный измеренный вывод проекта в том, что **решает кроппер, а не
модель**. На 29 типах с полосой `PP-OCRv6_medium_rec` даёт 0.552 exact match по полосе и 0.035
по целому кадру — в 16 раз хуже.

## Проверка разметки

```powershell
python tools\check_labels_and_roi.py dataset\out_ru
python tools\check_band_vs_answer.py dataset\out_ru
```

Чекер читает `labels.jsonl` и сверяет: совпадение `file` с PNG на диске, корректность `roi`
(прямоугольник в кадре, `text` внутри полосы), согласованность `answer` и `text`.

## Как читать датасет

```python
import json
from pathlib import Path

for labels in Path("dataset/full/data").rglob("labels.jsonl"):
    for line in labels.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        row = json.loads(line)
        image = labels.parent / row["file"]   # PNG рядом с меткой
        band = row["roi"]                     # [x, y, w, h] или None
        answer = row["answer"]               # что вводит игрок
        drawn = row["text"]                  # что нарисовано
```

Сводка по типам (число сэмплов, алфавит, длины меток, наличие полосы, лицензия) лежит в
`dataset_inventory.json` в корне датасета на Hugging Face.
