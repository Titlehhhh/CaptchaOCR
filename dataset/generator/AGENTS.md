# AGENTS.md — генераторы датасета (`dataset/generator/`, `dataset/generator_ru/`)

**Этот файл — вложенное правило. Он выигрывает у корневого `AGENTS.md` для файлов в этом каталоге**
(практика «ближайший AGENTS.md выигрывает»). Корневые правила (главный агент — оркестратор, один
файл — один агент, не выдумывать источники) действуют и здесь.

Задача каталога: **заново отрисовывать капчи 23 плагинов** так, чтобы у нас был датасет с точной
разметкой. Каждый генератор — перереализация алгоритма конкретного плагина.

---

## 1. Как добавить тип капчи

1. Создай файл `dataset/generator/dev/captcha/gens/<Plugin>.java`
   (для галерейных семейств `GalleryCaptcha` — `dataset/generator_ru/dev/captcha/gens/<Plugin>.java`).
2. Реализуй интерфейс `dev.captcha.Cg` (`dataset/generator/dev/captcha/Cg.java`):

| метод | обязателен | смысл |
|---|---|---|
| `String plugin()` | да | `owner/repo` апстрима, напр. `"LagBug/XProtect"`; в `generator_ru` — плоское имя |
| `String id()` | да | id типа, напр. `"map"`; он же имя папки в датасете |
| `String answer()` | да | что вводит игрок |
| `BufferedImage image()` | да | кадр, который видит игрок |
| `String source()` | да | **где живёт оригинальный алгоритм** (`класс#метод`) |
| `String prompt()` | нет | текст задания, если он не очевиден из картинки |
| `int[] roi()` | нет | полоса `[x, y, w, h]` с ответом, `null` — весь кадр и есть текст |
| `String text()` | нет | что **нарисовано**; по умолчанию = `answer()` |

3. **Больше ничего править не надо.** `dev.captcha.Gen` находит все публичные конкретные классы
   в `dev/captcha/gens` рефлексией, поэтому новый тип — это один новый файл. Вложенные
   `public static` классы внутри существующего файла тоже работают.
4. Пересобери и проверь (см. §4).

## 2. House rules (обязательны)

- **Faithful over pretty.** Тот же холст, тот же алфавит, тот же диапазон поворота/смещения, тот же
  порядок наложения шума. Это не «похожая картинка», а перерисовка.
- **Дефекты апстрима воспроизводятся, а не чинятся.** Недостижимый символ, мёртвая ветка, сверка по
  подстроке, заголовок с ответом — всё это повторяется и **документируется**. Решатель полезен
  против того, что он встретит в проде.
- **Режим реализации честно указывается**: `faithful` (построчно, лицензия позволяет), `clean-room`
  (алгоритм прочитан, код написан заново, без чужих идентификаторов), `reconstructed` (апстрим не
  найден, тип восстановлен по эталонным скриншотам). Для clean-room/reconstructed в `source()`
  пишется описание, а не выдуманный `класс#метод`.
- **`source()` обязателен и не выдумывается.** Не найден апстрим — пишем «не найдено» и `reconstructed`.
- **Случайность:** один `new Random()` на экземпляр генератора; `Gen` создаёт новый генератор на
  каждый сэмпл. Не дели статический `Random` между классами.
- **Пользуйся `Img` и `McUi`** (общее ядро `dataset/generator/dev/captcha/`) для холстов, шрифтов,
  шума и Minecraft-UI поверхностей, а не изобретай свои.
- **Плагину, который не рисует картинку, генератор не полагается** — он документируется в
  `reports/SITE_CAPTCHAS.md`. Выдуманная картинка была бы выдумкой, а не перереализацией.

## 3. Правило полосы (`roi`)

**Полоса, которая не помещается в кадр, — это не полоса.** `roi()` возвращает `null`, а не
прямоугольник, в который попал только кусок ответа.

Большинство наших типов — **сцены** (чат-лог, окно инвентаря, диалог наковальни, веб-панель):
ответ — одна строка из нескольких. Распознавателю, которому показали весь кадр, задача поставлена
некорректно: он выучит раскладку («строка после `Tries Left:`»), которая не переносится на другой
плагин. Генератор знает, где нарисовал ответ, — отдайте этот прямоугольник.

`text()` по умолчанию равно `answer()`. Переопределяйте его там, где на картинке нарисовано не то,
что вводит игрок: семейство чисел-words (на картинке «шестьсот девяносто», игрок вводит `690`).

## 4. Как проверить

```powershell
$java = "I:\ForAndroid\Java\21\bin"
$core = Get-ChildItem -File dataset\generator\dev\captcha\*.java | % FullName
& "$java\javac.exe" -encoding UTF-8 -d build\classes -sourcepath dataset\generator $core (Get-ChildItem -Recurse -Filter *.java dataset\generator | % FullName)
& "$java\javac.exe" -encoding UTF-8 -d build\classes_ru -sourcepath dataset\generator_ru $core (Get-ChildItem -Recurse -Filter *.java dataset\generator_ru | % FullName)
& "$java\java.exe" "-Djava.awt.headless=true" -cp build\classes    dev.captcha.Gen      dataset\out    100
& "$java\java.exe" "-Djava.awt.headless=true" -cp build\classes    dev.captcha.Validate dataset\out
& "$java\java.exe" "-Djava.awt.headless=true" -cp build\classes_ru dev.captcha.Gen      dataset\out_ru 100
& "$java\java.exe" "-Djava.awt.headless=true" -cp build\classes_ru dev.captcha.Validate dataset\out_ru
python tools\restore_real_shots.py      # вернуть real_shots/ после пересборки
python tools\check_labels_and_roi.py dataset\out_ru
python tools\check_band_vs_answer.py dataset\out_ru
```

- **`build.ps1` выполнить нельзя** (запуск `.ps1` на этой машине заблокирован) — используй
  инлайн-блок выше, он и есть логика `build.ps1`.
- **Полосу проверяй глазами**: `dataset/out/index.html` и `dataset/out_ru/index.html` — контактные
  листы. Автоматика не умеет смотреть картинки: `Validate` считает цвета и дубликаты, но не видит,
  что ответ попал в полосу. Известный пример сломанной полосы: `Archy-X/Krypton/map` — ширина на
  4 px ýже текста, пятый символ попадает за полосу (`Krypton.java`: ширина считается как сумма
  ширин глифов, а рисунок оставляет между глифами по одному пустому пикселю).
- **Датасет — артефакт машины**: шрифты зависят от системы, поэтому датасет генерируется один раз
  и с него потом учат. Пересборка на другой машине даст другие пиксели.
