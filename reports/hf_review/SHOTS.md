# Скриншоты живых страниц Hugging Face

Снимал субагент №2. Правил только `reports/hf_review/shots/` и этот файл; карточки не менял.

- <https://huggingface.co/datasets/Titlehhhh/captchaocr-dataset>
- <https://huggingface.co/Titlehhhh/captchaocr-ppocrv6>

## Как снято

Headless Edge, отдельный профиль (`%TEMP%\edge-hfshots`), тёмная тема Hub по умолчанию, DPR 1:

```
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new --disable-gpu ^
  --hide-scrollbars --force-device-scale-factor=1 --user-data-dir="$env:TEMP\edge-hfshots" ^
  --window-size=1440,1200 --virtual-time-budget=20000 --screenshot="<abs>.png" "<url>"
```

Полную страницу headless Edge не умеет: снимается только окно. Поэтому «вся карточка» — это
снимок с окном на всю высоту страницы (1440×6000 … 1440×12000) плюс нативные кропы 1:1 из него.
Якоря (`#how-to-load-it`) **не сработали**: headless делает скриншот верха документа, оба снимка
вышли пустыми и удалены.

Оговорки, без которых выводы будут неверными:

- `--hide-scrollbars` прячет **и внутренние** полосы прокрутки, поэтому переполнение внутри
  `<pre>`/таблиц на снимках выглядит жёстким обрывом строки. Есть ли на живой странице полоса
  прокрутки внутри блока — этим снимком не доказать: флаг её убирает. Утверждать можно только то,
  что контент шире контейнера.
- Тёмная тема выбрана Edge по умолчанию (`prefers-color-scheme: dark`), светлую не снимал.
- Не авторизован: кнопки Like/Follow в состоянии «0», приватных элементов нет.

## Датасет: что видно

**Десктоп 1440, первый экран** — `dataset-desktop-fold.png`. Нормально. Шапка Hub, заголовок
`Datasets: Titlehhhh/captchaocr-dataset` с Like 0, три ряда бейджей (Tasks / Modalities / Formats /
Languages / Size / Tags / Libraries / License), вкладки `Dataset card · Data Studio · Files and
versions [xet] · Community 1`. Всё это — верхние 280 px. Дальше **весь остаток первого экрана занят
dataset viewer'ом**: таблица на 6 строк, у `image` колонки вместо превью написано `unknown` и стоят
серые прямоугольники-заглушки, `file`-колонка — обрезанные `001.png …`, справа за краем колонки
`token` (виден только огрызок). Проза карточки начинается на y≈900 из 1200: заголовок
«CaptchaOCR — Minecraft anti-bot captchas as Parquet», 2 вводных абзаца. То есть на первом экране
пользователь видит чужой грид данных и только в последней трети — саму карточку.

**Десктоп целиком** — `dataset-desktop-full.png`. Нормально. Порядок: viewer → вступление → Files
(9 шардов, таблица `shard / rows / bytes`) → Schema (7 колонок: column, arrow type, nullable,
meaning) → How to load it (3 блока кода) → The band rule → text may differ from answer → The 20 types
(таблица из 5 колонок) → Provenance and honesty (6 буллетов) → LICENSE. Таблицы читаются, код не
разъезжается, пустых провалов нет. Правая колонка (сайдбар) заканчивается на y≈700 и дальше пустая
до самого низа — вертикальная линия-разделитель сайдбара при этом идёт на все 6000 px.

**Планшет 640** — `dataset-tablet-640.png`. Нормально: заголовок и все бейджи влезают, вкладки
влезают (`Files [xet]`), кнопки Copy to bucket / Use this dataset на всю ширину, сайдбар ушёл
наверх над viewer'ом. Viewer по-прежнему шире экрана.

**Телефон 390, первый экран** — `dataset-mobile-fold.png`. Противно. Заголовок, бейджи и кнопки
обрезаны справа: видно `Rus…`, `Synth…`, `×et`, «Like 0» вообще за кадром, от `Copy to bucket` и
`Use this dataset` отрезан правый край (кнопка `⋮` не видна совсем). Вкладка `Files and versions`
сжалась до `Files`. Сайдбар-карточки (Downloads 224, Number of rows 200 000, 2.05 GB) — на всю
ширину, но тоже с отрезанным правым краем. **Прозы карточки в первом экране нет вообще**, viewer
начинается только на y≈925 (за пределами 844).

**Телефон, вся карточка** — `dataset-mobile-full.png` + 3 кропа. Противно, и это главный вывод.
Страница **не переразложилась под 390**: контент остался шириной ≈600 px и уезжает вправо, так что
в кадре виден только левый обрез.
- `crop-dataset-mobile-load.png`: таблица Files обрезана (`257,651,` — байты уходят за экран),
  таблица Schema обрезана сразу после `nullable`, колонка `meaning` **целиком за экраном**.
- `crop-dataset-mobile-types.png`: абзацы обрываются на середине предложения («one row per sam…»),
  код обрывается на `load_dataset("Titlehhhh/captchaocr-dat…`, `# rows: 200,0…`, `row["image"]`.
- `crop-dataset-mobile-end.png`: таблица «The 20 types» показывает **только колонку `type_id`**,
  остальные четыре (plugin, captcha, samples, dims) недоступны; буллеты Provenance тоже обрезаны
  на середине фразы.

Видно при этом: viewer на телефоне всё-таки рендерится (Split / train / 200k rows / Search this
dataset / шапка таблицы), но toolbar обрезан — `Duplicate`, `Data Studio` и меню уехали вправо.

## Модель: что видно

**Десктоп 1440, первый экран** — `model-desktop-fold.png`. Нормально. Заголовок
`Titlehhhh/captchaocr-ppocrv6`, бейджи (Image-to-Text, Transformers, Safetensors, датасет, English,
Russian, теги, apache-2.0), вкладки `Model card · Files and versions [xet] · Community`. В отличие
от датасета, здесь **проза начинается сразу**: заголовок карточки, лид-абзац, выделенная цитата-
дисклеймер про `universal_v1`, заголовок «What is in this repository» и таблица из 7 файлов.
Справа — Downloads 83 со спарклайном, Safetensors (19.2M params), Inference Providers (не
развёрнут), Model tree, Dataset used to train. Первый экран информативный, глазам есть за что
зацепиться — но таблица `file / what it is` уже на всю высоту кадра.

**Десктоп целиком** — `model-desktop-full.png`, `model-desktop-tall.png`, 4 кропа. Нормально по
вёрстке, противно по объёму. Карточка кончается на **≈11 940 px** (футер виден в снимке 1440×12000,
кроп `crop-model-end.png`): это **≈10 экранов** по 1200 px. Порядок: What is in this repository →
Provenance (key-value таблица) → What changed in the head → The training run in numbers → What was
trained on, and what was not (2 таблицы) → Measured results → Types the model was trained on (таблица
18 строк) → Types the model never saw (таблица 6 строк) → caveat → No weight interpolation (таблица
α) → What this model is NOT good at → How to use it (код) → band vs screenshot → The dataset this was
trained on → Provenance and licence → Reproducing (код) → футер.

Что именно сломано:
- **Колонка `n` переносит число `1500` на две строки** — в `crop-model-tail.png` она читается как
  `1` над `500`, то есть выглядит как n=1. Это не косметика: рядом в той же таблице `n` бывает
  `200`, и цифра `1` в отдельной строке читается как «один пример».
- Подпись строки `text ≠ answer` в key-value таблице переносится на две строки
  (`crop-model-end.png`), потому что левая колонка уже 130 px.
- Таблица Measured results сжата в 600 px: заголовок `exact (zero step)` переносится на 4 строки,
  столбцы чисел жмутся (`crop-model-measured.png`).
- Блоки кода обрезаны по правому краю 600-пиксельной колонки: `PPOCRv6Sm…`,
  `# a crop of the …`, `px = proc(images=[image], … # 48…` (`crop-model-bottom.png`).
- **Пустая колонка сайдбара на всю высоту**: сайдбар кончается на y≈840, а его вертикальный
  разделитель тянется до футера — 11 000 px пустой правой половины экрана.

**Планшет 640** — `model-tablet-640.png`. Нормально: сайдбар поднялся наверх над карточкой, текст
переносится по 592 px, бейджи и кнопки влезают целиком. Именно этот снимок доказывает, что дело не
в «держит десктопную вёрстку», а в конкретном пороге ширины.

**Телефон 390** — `model-mobile-fold.png`, `model-mobile-full.png`. Противно. В первом экране одна
шапка: бейджи обрезаны (`Russian`, `pp-oc…`), спарклайн Downloads уезжает за правый край, `Use this
model` обрезана, `Files info` обрезана, `Ask for pro…` обрезана, `PaddlePaddle/PP-OCRv6_medium_rec…`
обрезана. **Заголовка карточки в первом экране нет** — он появляется примерно на y≈1000, то есть
первый экран целиком отдан метаданным. Дальше по всей странице: key-value таблица Provenance
показывает только левую часть значений, таблицы результатов сжаты в левые ~55 % ширины, код
обрезан. Высота на 390 заметно больше 5000 px (снимок 5000 не доходит даже до «Types the model never
saw»).

## Ответы на прямые вопросы брифа

- **Галерея примеров**: нет ни на одной из страниц. У датасета `image`-колонка в viewer'е — серые
  заглушки с надписью `unknown`, превью капч не рендерятся. У модели картинок нет вообще, только
  спарклайн загрузок. То есть по карточке **нельзя увидеть, как выглядит капча**, которую решает
  модель, — а это первое, что ищет читатель.
- **Dataset viewer**: на датасете есть и на десктопе занимает почти весь первый экран; на телефоне
  есть, но с обрезанным toolbar'ом.
- **Кнопки**: `Use this dataset` / `Use this model`, `Copy to bucket`, `Deploy` — есть, на десктопе
  справа сверху, на телефоне в отдельном ряду и обрезаны справа.
- **Badges/теги Hub**: датасет — Image-to-Text, Tabular, Text, parquet, English, Russian, 100K–1M,
  captcha / ocr / minecraft / anti-bot / Synthetic / parquet, Datasets+ 3, `mixed-per-plugin-licences`.
  Модель — Image-to-Text, Transformers, Safetensors, ссылка на датасет, English, Russian,
  `pp_ocrv6_small_rec`, captcha, ocr, minecraft, pp-ocrv6, text-recognition, cyrillic, `apache-2.0`.
  Всё это корректно и без мусора.
- **Cookie-баннер**: отсутствует на всех снимках, ничего не перекрывает. Рекламы нет.

## Пять наблюдений

1. Порог адаптивности лежит между 390 и 640 px: на 640 обе страницы целые, на 390 — обрезаны
   справа. Верхняя граница переполнения не измерена точно (бисекцию не делал).
2. Первый экран на телефоне у обеих страниц — это шапка и метаданные; ни на датасете, ни на модели
   из него не видно ни названия карточки, ни единой строки прозы.
3. У датасета первый экран на десктопе отдан viewer'у: проза начинается на 75 % высоты экрана.
4. Карточка модели — 11 940 px на 1440, то есть ~10 экранов прокрутки; сайдбар при этом кончается
   на 840-м пикселе, и его вертикальная линия делит пустоту до самого футера.
5. Ни одна страница не показывает ни одного примера изображения: у датасета `image`-колонка — серые
   заглушки `unknown`, у модели картинок нет.

## Три главных визуальных раздражителя

1. **Телефон: страница шире экрана.** Обрезаны абзацы, код, таблицы (у «The 20 types» из пяти
   колонок видна одна), бейджи и кнопки. Ощущение сломанной страницы, а не мобильной версии.
2. **Модель: ~12 000 px текста без якорей.** Плотная стена: 7 разделов с таблицами и двумя блоками
   кода, ни одной картинки, ни одного collapse/аккордеона. Читатель не понимает, где остановиться.
3. **Пустая правая половина на всю высоту** (модель, 1440): сайдбар кончается на 840-м px, а его
   рамка продолжается до футера — ~11 000 px пустоты с вертикальной чертой посередине страницы.

Плюс два мелких, но конкретных: число `1500` в колонке `n` переносится как `1` / `500`, и колонка
`meaning` в таблице Schema на телефоне недоступна полностью.

## Что проверено / что нет

Проверено: все 19 PNG открыты и описаны; размеры файлов; отсутствие cookie-баннера; наличие кнопок,
вкладок, viewer'а, тегов; высота страницы модели (футер в снимке 12000); поведение на 1440 / 640 / 390.

Не проверено: светлая тема; авторизованное состояние (звёзды, «like», приватные бейджи); реальная
мобильная эмуляция с touch-метатегом и мобильным UA (снимал только по ширине окна — на живом
телефоне Hub может отдать другой layout); точная ширина переполнения (не бисектировал 390↔640);
Firefox/Safari.

Расхождений с карточками не искал — это не моя зона; контент не менял.
