## 2. Что увидел — глазами

### 2.1 Первый экран v1 (`01_first_screen.png`)

Это **сильный первый экран**. За 10 секунд человек видит: крупный заголовок, два абзаца «что это»
и — главное — **сетку из настоящих капт** 3×3, с подписями под каждой (тип · размер ·
описание · **золотой ответ**). Подписи читаются, картинки не мелкие, таблица не «едет»:
рамки ровные, колонки не разъезжаются. Ровно тот эффект, ради которого затевалась правка.

Нюансы:
* Заголовок **переносится на две строки** — на 1280 это ~60 px.
* Между лидом и галереей стоит `---`, а **между галереей и «Что это такое» — нет**:
  галерея визуально приклеивается к следующему текстовому блоку.
* Сразу после галереи начинается блок «Что это такое» (7 абзацев, ~1 100 px). Он стартует
  на y≈1377, то есть **первый экран закрывается на первой строке этого блока**. Тот, кто
  проскроллил, сразу упирается в стену текста.

## 4. Рекомендация: что спрятать под `<details>`

### 4.1 Проверка, что `<details>` работает в GitHub

Проверено через `gh api --method POST markdown` (тот же GFM-движок, что и на странице):

| проба | результат |
|---|---|
| `<details>` + `<summary>` | ✅ рендерится как `<details><summary>…</summary>` |
| markdown-таблица **внутри** `<details>` | ✅ рендерится полностью (`<table role="table">`, thead/tbody, 23 тега `<code>`) |
| `**жирный**` и `` `код` `` внутри `<details>` | ✅ работают |
| список `- пункт` внутри `<details>` | ✅ работает |
| картинка `![]()` внутри `<details>` | ✅ работает (`<img src=… style="max-width:100%">`) |
| **два `<details>` подряд, между ними обычный текст** | ✅ работают независимо (проверено на v2: 3 `<details>`, 3 `<summary>`) |

⚠️ **Единственное ограничение, найденное при проверке:** если `<details>` стоит **внутри
markdown-таблицы** (то есть `<details>` — это ячейка), GFM не разбирает markdown внутри ячейки —
там нужен сырой HTML. Схема «`<details>` в ячейке» не годится; `<details>` ставится **между**
таблицами. Это уже сделано правильно в v2.

Готовый фрагмент из §4.3 проверен как отдельный файл (`build/fragment_test.md` →
`build/fragment_test.html`): 1 `<details>`, 1 `<summary>`, 2 `<table>`, 23 `<code>` — **VALID**.
