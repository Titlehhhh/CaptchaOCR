# Семейство «стандартные капчи V1» из группы типов GalleryCaptcha: что это, кто делает, есть ли у нас

**Дата:** 2026-10-22 · **Источники:** локальные референсы `<gallery-refs>/` (343 картинки секции
`s00_Стандартные_капчи_V1`), документация галереи, отчёт по коммерческим сервисам,
`reports/SITE_CAPTCHAS.md`. **Ничего не выдумано:** где точного ответа нет — так и написано.

---

## 1. Коротко (TL;DR)

1. **«Стандартные капчи V1» — это не один тип, а витрина «общей модели».** По документации галереи:
   *«API V1 — Общая модель для капч, где написан англ. текст*» ([documentation.pw/versions.html](https://documentation.pw/versions.html)).
   V1 — это **модель**, а галерея показывает, на каких **стилях** она едет.
2. **Секция V1 — самая большая в каталоге: 343 картинки** из 525, и она **неоднородна по холсту**:
   230 картинок 250×150, **112 картинок 150×90** и одна 384×256.
3. **112 картинок внутри V1 — это веб-капчи**, то есть ровно семейство V6 («модель капч, обученная на
   капчах с сайтов»): белый фон, синий искажённый текст, зелёные волнистые линии. **У нас это семейство
   есть** — `GalleryCaptcha/ru-web` (150×90), наша реконструкция V6.
4. **Остальные 230 (250×150) — другое семейство: «код поверх игровой сцены».** Фон — скриншот/арт,
   поверх крупный цветной код (зелёный, ~40 px), поверх же мелкий «мусорный» текст другого цвета
   (красный), плюс шумовые линии и дуги. **Этого семейства у нас нет.**
5. **Кто именно делает V1-сцену — не найдено.** Найденная единственная русская реализация
   (`gm-captcha` / UCRAFTS) **не совпадает**: она рисует сплошной фон `#bca881` и по своему же `.env`
   вообще **не рисует** линий и точек шума.
6. **Рекомендация:** семейство **стоит добавлять** (это 2/3 самого массового типа в каталоге и новый
   для нас домен «шум + фон + две наложенные строки»), но **сначала нужна идентификация** — из какого
   плагина оно; реконструкция «по картинкам» возможна, но упирается в юридический вопрос использования
   референсов.

## 2. Что именно лежит в секции V1 (измерено локально)

Каталог `<gallery-refs>/`, секция `s00_Стандартные_капчи_V1`:

| размер холста | картинок | что это |
|---|---|---|
| 250×150 | 230 | «игровая сцена» (код поверх фона-сцены) |
| 150×90 | 112 | веб-капчи (семейство V6) |
| 384×256 | 1 | единичный выброс |

Для сравнения, остальные секции: `s08_API_V6_Веб_капчи` — **все 70 картинок 150×90**; `s02/s03` (русские

### 2.1 Визуальный характер (просмотрено 6 картинок из разных)

**Подтип «игровая сцена» (250×150):**
- `001.png` — фон: снежная деревня Minecraft, персонажи, постройки; поверх крупный **зелёный** код
  (без засечек, ~40 px высотой, изогнутые глифы); сверху мелкий **красный** «мусорный» текст
  (что-то вроде `ONK3? pinquin220 90 3 topDe…`) и мелкие декоративные элементы по краям.
- `004.png` — тот же принцип, но фон плотнее и цветнее, красная цифра `6` и `3` поверх.
- `012.png` — «мультяшный» красно-синий фон-шум, чёрный искажённый код и **чёрная дуга** через весь кадр.
- `020.png` — пастельный абстрактный фон, **зелёный** код и несколько **зелёных прямых линий**-шумов.
- `007.png` — серо-белый **геометрический/полигональный** фон (рисуется процедурно, не фото), тёмно-серый
  код и множество тонких кривых.

Выводы: **фон может быть и скриншотом, и процедурной абстракцией**; шум — это линии и дуги поверх;
**текст бывает двух слоёв** (крупный код + мелкий мусорный текст другого цвета) — это важно: задача
«какая из строк ответ» возникает уже здесь.

**Подтип «веб-капча» (150×90):**
- `056.png` — белый фон, **синий** искажённый текст, **зелёные** волнистые линии поверх. Это
  классическая веб-капча, и это **точная наша семья** `GalleryCaptcha/ru-web`.

### 2.2 Про размер 250×150 — это размер галереи, а не нативный

В архивном FAQ галереи: «Какой размер капчи самый лучший?» → **250×150**; и клиент на Java
(``) **приводит картинку к 250×150** перед отправкой (`setResize(true)`).
Значит, игровые кадры в галерее, скорее всего, **отмасштабированы**, и нативный размер неизвестен —
это надо помнить при попытке построить генератор.

## 3. Что входит в семейство V1 (по архивной документации галереи)

[documentation.pw/versions.html](https://documentation.pw/versions.html) — список ключевых версий:

| версия | что это |
|---|---|
| **V1** | **«Общая модель для капч, где написан англ. текст»** |
| V1.1 | «Версия, использующая ChatGPT для распознавания» (вендор снимает с себя ответственность) |
| V2 | капчи русским текстом прописью («двести сорок три») |
| V3 | капчи русскими буквами («чхЩ, рРп») |
| V4 / V5 / V52 / V53 | пазлы и вращение рамок 3×3 / 2×2 |
| V6 | «Модель капч, обученная на капчах с сайтов» |
| B1 | «Версия, которая решает капчи квадратным шрифтом» |

Версия выбирается префиксом ключа (`V52_…`, `B1_…`); для V1 префикс не нужен.
**Следствие для нас:** «V1» — это **общая латинская модель** вендора, а не один тип картинки. Галерея
показывает, что её кормит как минимум два разных стиля (веб-капчи и игровые сцены) — поэтому
«найти в каталоге V1» и «найти тип V1» — разные задачи.

**Про собственные модели вендора:** в ленте обновлений (снапшот 2025-04-17, `/updates`) —
«The model was redesigned into a custom CNN» и «New neural network model» 16.03 / 14.04 / 15.04.2025
(дважды: отдельно для чисел прописью и для кириллицы). То есть **CNN у них своя**, не Securimage и не
PaddleOCR. Детали — в отчёте по коммерческим сервисам.

## 4. Кто делает «код поверх игровой сцены»

### 4.1 Что проверено и ОТВЕРГНУТО

`UCRAFTS/CaptchaPlugin` (автор oDD1 / Alexander Repin) — единственная найденная русская реализация,
которая рисует картинку; рендерер — npm **`gm-captcha` 1.0.2** ([github.com/eidonjoe/gm-captcha](https://github.com/eidonjoe/gm-captcha), **MIT**), сервис — `UCRAFTS/CaptchaService` (Express + Redis). Параметры из `.env`:
`CAPTCHA_WIDTH=512`, `CAPTCHA_HEIGHT=256`, `CAPTCHA_BACKGROUND=#bca881`, `CAPTCHA_FONT_SIZE=64`,
`CAPTCHA_MAX_SWIRL=128`, `CAPTCHA_MAX_SHEAR=8`, `CAPTCHA_PATTERN=йцукенгшщзхъёэждлорпавыфячсмитьбю1234567890`.

**Оно не совпадает с V1-сценой**, и это установлено точно:
- фон — **сплошной цвет `#bca881`**, а не сцена и не абстрактная графика;
- сервис передаёт `lineCount = -1` и `pointCount = -1`, а циклы `gm-captcha` — `for (i = 0; i < lineCount; i++)`
  → **линий и точек шума не рисуется вообще**;
- алфавит — русская раскладка, а V1 — латиница;
- размер 512×256, а в галерее всё приведено к 250×150.

Вывод (совпадает с выводом `reports/SITE_CAPTCHAS.md` §7.6): **gm-captcha — не источник V1-сцен.**

### 4.2 Кандидаты по признаку «капча поверх игровой сцены» (ещё не проверены)

- [SpigotMC «Captcha» 75891](https://www.spigotmc.org/resources/captcha.75891/) — «map-based system that
  looks like a real captcha» (описание с сайта).
- [LofiWebCaptcha](https://www.spigotmc.org/resources/lofiwebcaptcha-ВебКапча-bukkit.121901/) —
  «веб-капча» для Bukkit/BungeeCord.
- BetterCaptcha, HightMapCaptcha, CaptchaGUI, CaptchaVerifyZ — из нашей `reports/SITE_CAPTCHAS.md`.

### 4.3 Общие генераторы «фон-картинка + шум» — не подходят по признакам

Искал по запросам «captcha generator background picture distorted text noise lines», «Securimage vs
kCaptcha differences», «генератор капчи фоновая картинка шум». Классика такого рода — **Securimage**
(фон-картинка + дуги/точки, плоский холст 200×50), **kCaptcha** (искажённый текст на фоне-картинке,
200×50), CaptchaGen, PHP-генераторы на GD/Imagick. **Ни один не даёт наблюдаемую картину V1:**
у V1 холст 250×150 (или приведён к нему), фон — игровая сцена, **два наложенных текста разных цветов**,
шум — линии/дуги. Отличие не в деталях, а в самой композиции.

**Итог: точный плагин/библиотеку, делающую V1-сцену, НЕ НАЙДЕЛ.** Где искал: поиск по-русски и
по-английски (minecraft captcha plugin background image code green text; капча для minecraft плагин
фоновая картинка код зеленым; captcha generator background picture distorted text noise lines php
FAQ и документация галереи (архивный снимок от 2025-05-03), а также наш
собственный `reports/SITE_CAPTCHAS.md`.

## 5. Отличие от V6 — это разные ветки

| | V6 («веб-капчи») | V1-сцена («стандартные капчи») |
|---|---|---|
| холст | 150×90 | 250×150 (в галерее; нативный неизвестен) |
| фон | белый/декоративный | игровая сцена или процедурная абстракция |
| текст | одна строка, 5 символов | **две строки**: крупный код + мелкий «мусор» |
| шум | волнистые линии | линии, дуги, «мусорный» текст |
| наш аналог | **`GalleryCaptcha/ru-web` (есть)** | **нет** |

Это **разные ветки**: наша `ru-web` — реконструкция V6 (150×90, белый фон с декором, один код), V1-сцена —
отдельное семейство. Смешивать их в один тип нельзя: у них разная композиция, разный шум и разная
задача выбора ответа (в V1-сцене строк несколько).

Отдельно: **112 из 343 картинок секции V1 — это V6-семейство** (те самые 150×90). То есть наш
`ru-web` покрывает примерно треть V1-витрины, а оставшиеся две трети — не покрыты.

## 7. Стоит ли добавлять и сколько это работы

**Ценность — высокая:**
- это **2/3 самой массовой секции** каталога (230 из 343), то есть самый ходовой тип у вендора;
- для нас это **новый домен**: шум + фон + **две наложенные строки**, где нужен выбор ответа. Ровно тот
  класс, где наш текущий CRNN проваливается (0.000 на невиданных типах), и ровно тот, где нужна связка
  «детектор + правило выбора строки», которую мы и так собираем строить;
- по вендорской статистике, V1 — «общая модель», и она держит 95–99 % по их заявлению, значит, тип
  решаемый, а не экзотический.

**Трудоёмкость — зависит от того, найдём ли апстрим:**
1. **Идентификация (главный шаг).** 230 картинок — достаточный материал: по ним можно понять, из каких
   плагинов они (сравнить с уже измеренными 18 плагинами — не совпало) и, возможно, выйти на
   SpigotMC-ресурс по описанию («map-based system that looks like a real captcha»). Оценка: **полдня-дня**
   на поиск и сверку.
2. **Если апстрим найден** — генератор пишется по образцу наших `dataset/generator/dev/captcha/gens/*.java`
   (одно слово «сделай новый тип капчи» в `AGENTS.md` §5), с переносом алгоритма. Оценка: **1–2 дня**
   вместе с пересборкой и валидацией.
3. **Если апстрим не найден и делаем «по картинкам»** — нужны: текстуры фона (у нас 230 референсов),
   понимание второго «мусорного» слоя текста и подбор его шрифтов. Оценка: **2–4 дня** и юридический
   вопрос (см. ниже).

**Юридическая оговорка — обязательна к прочтению.** В правилах галереи («/rules», снапшот 2025-04-17)
запрещено использование API для обучения собственных моделей; в архивном FAQ галереи
это зафиксировано как «правило "запрещено использовать картинки галереи для обучения собственных моделей"».
**Перед тем как брать референсы из `<gallery-refs>/` как обучающий материал, нужно прочитать точную
формулировку** правил (в `the archived gallery page` и снапшоте `/rules`): запрет касается
использования **сервиса/API** или также **картинок**? Я не проверял формулировку построчно — это
проверяемый вопрос, и его надо закрыть первым.

## 8. Рекомендация

1. **Закрыть юридический вопрос** (формулировка `/rules`): можно ли использовать 230 референсов как
   обучающий материал. Это дешёво и блокирует всё остальное.
2. **Провести идентификацию** семейства: есть ли плагин в экосистеме Spigot/Paper/velocity, который
   рисует код поверх игровой сцены с двумя слоями текста. Наш `research/` уже содержит заготовки
   (`research/candidates/`, `the archived gallery page`) — искать там.
3. **Не добавлять тип «по памяти»**, пока не подтверждён источник: V1-сцена — самая массовая, и ошибка
   в источнике (как с gm-captcha) обесценивает тип целиком.
4. **Параллельно** (независимо от идентификации) — этот тип стоит добавить **в тест нашего конвейера**:
   даже имея лишь референсы, можно собрать контрольный набор «шум + фон + две строки» и проверить, что
   детектор+правило выбора ответа работают. Это дешевле, чем строить генератор.

## 9. Что не проверено (честно)

- **Точный плагин/библиотека, делающая V1-сцену, — не найдено.** Перечисленные выше кандидаты не
  проверены чтением их исходников (кроме gm-captcha, который проверен и отвергнут по документации).
- **Нативный размер капчи V1** — неизвестен: 250×150 в галерее может быть размером приведения.
- **Точная формулировка правил галереи** про использование картинок для обучения — не вычитывалась
  построчно; в отчёте D она пересказана.
- **Кодировка имени файла на хостинге** (`the archived gallery file`) — правило не найдено.
- **Второй «мусорный» текст** в V1-сцене — что это (другой код? случайные символы? подпись?) — по
  картинкам не установлено однозначно.
- 112 картинок 150×90 внутри секции V1 приняты за V6-семейство **по одному просмотренному образцу**
  (`056.png`); остальные 111 не открывались.
